Spec v0.2

The package standard for agent-operable work.

Workflowware does not merely describe how work should be performed. It encodes the discipline by which work is performed, checked, corrected, audited, and handed off.

View SPEC.md on GitHub → Open package template

The work discipline

A job is not complete just because the agent returned text.

Every governed run moves through a lifecycle. COMPLETE is reachable only after verification, audit, and handoff — never by silently passing a failed check.

READY -> RUNNING -> VERIFYING -> REPAIR_REQUIRED | VERIFIED
     -> AUDIT -> HANDOFF_READY -> COMPLETE

No silent progression after failed verification.
calculate -> apply -> inspect -> correct -> continue.

Definition

What a package must do.

State the job, define the procedure, declare authority, specify the checks, the repair path, the audit criteria, the evals, and the handoff record.

Required layers

Concepts every kit carries.

Human trust surface

What it does, why it exists, how it’s controlled, and what proof exists.

Workflow spec

Trigger, context, procedure, finish line, edge cases, success metrics, executable graph.

Agent spec

Role, inputs, tools, allowed/prohibited actions, outputs, escalation, model hint.

Checks

What must be verified, how, and by whom (which audit level).

Repair

The correction procedure for a failed check.

Audit

Whole-job conformity criteria and the evidence the run must produce.

Evals

Example inputs and expected behavior you can test and improve.

Handoff + manifest

Install path, customization notes, and machine-readable package map.
